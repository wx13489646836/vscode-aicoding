# Titanium Workshop 页面介绍

本文档用于说明 `titanium-cup-showcase` 首页的整体设计思路、页面结构、核心功能、交互机制和技术实现重点。该页面定位为一个高端纯钛杯产品展示页，兼具品牌叙事、商品转化、产品矩阵展示、3D 交互体验和智能客服入口。

## 1. 页面总体定位

该页面不是一个普通商品详情页，而是一个偏“品牌官网 + 单品展示 + 产品目录入口”的复合型落地页。页面围绕主推产品 `Han Dynasty Heavenly Horse Pattern Pure Titanium Thermos` 展开，通过视觉、文案、图片、视频和 3D 模型共同传达以下信息：

- 产品材质：99.95% 纯钛、抗菌、耐酸碱、无金属异味。
- 文化价值：汉代天马纹样、丝路文物灵感、中国传统艺术符号。
- 工艺质感：金属纹理、礼盒包装、茶滤结构、内外纯钛细节。
- 交互体验：支持图片/视频浏览、3D 模型拖动旋转、滚轮缩放、智能客服问答。
- 商业目标：引导用户查看产品、了解卖点、进入产品列表或发起购买。

整体页面面向的用户可以分为三类：

1. 首次接触品牌的访客，需要快速理解产品定位和品牌调性。
2. 对纯钛杯、保温杯、礼品杯感兴趣的潜在买家，需要看到材质、功能、价格和购买入口。
3. 对产品细节有更高要求的用户，需要通过 3D 模型、视频、场景图和客服问答确认细节。

## 2. 视觉设计思路

### 2.1 总体风格

页面采用深色高端金属风格，主视觉基调为黑色、深棕、暗金和冷灰，整体接近“高级器物展厅”而不是传统电商大促页面。

设计关键词：

- 深色背景
- 金属质感
- 暗金点缀
- 大留白
- 产品居中展示
- 英文大写导航
- 品牌展厅感
- 科技与东方文化结合

这种设计策略的作用是降低廉价电商感，突出“纯钛工艺品”的价值感。页面没有使用高饱和促销色，也没有密集优惠信息，而是通过节制的版式、暗色背景和产品图来营造高级感。

### 2.2 背景系统

背景由 `ChineseBackground` 组件负责，主要包含：

- 深色线性渐变，形成整体金属暗面。
- 跟随鼠标位置变化的微弱暖色径向光斑。
- SVG 噪声纹理，模拟金属颗粒感。
- 顶部暗金发丝线，作为品牌质感细节。
- 左右暗角和底部阴影，增强页面纵深。

这个背景系统的目标不是抢占视觉，而是为产品图、3D 模型和白色文字提供稳定的“展示空间”。鼠标跟随光斑提供了轻微动态反馈，使页面不显得完全静态。

### 2.3 色彩策略

页面主色系统可以概括为：

| 类型 | 用途 | 代表颜色/效果 |
|---|---|---|
| 主背景 | 页面底色、展厅氛围 | 深黑、深棕、暗灰 |
| 主文字 | 标题、品牌名 | 白色 |
| 次级文字 | 描述、说明 | 灰色 |
| 强调色 | 标签、价格、文化卖点 | 琥珀金 / 暗金 |
| 操作色 | 3D 控件、客服状态 | 蓝色 |

暗金色主要用于强化“高端、礼品、工艺、文化传承”的感受；蓝色主要用于功能性控件，比如智能客服和 3D 控制按钮，避免和品牌金色混淆。

### 2.4 字体与排版

页面使用英文大写导航和高字距标题，形成较强的品牌官网感。标题层级清晰：

- 一级标题：`Pure Titanium Collection`
- 模块标题：`FEATURED PRODUCT`、`3D & VR VIEW`、`CRAFTED FOR EVERY MOMENT`
- 场景标题：`Han Dynasty Heavenly Horse`、`Pure Titanium, Inside & Out` 等

页面大量使用 `tracking` 字距，尤其在导航、模块小标题和按钮中。这种处理让页面更接近奢侈品/工艺品官网，而不是普通零售站点。

## 3. 页面信息架构

首页按照用户浏览路径从“品牌认知”逐步推进到“产品理解”和“转化入口”：

1. 顶部导航
2. Hero 品牌首屏
3. 主推产品展示
4. 3D & VR 交互模型
5. 产品体验场景
6. 推荐产品矩阵
7. 页脚导航
8. 浮动智能客服

这种结构的逻辑是：

- 先建立品牌调性。
- 再展示主推产品。
- 再用交互模型增强可信度。
- 再用场景图讲清楚卖点。
- 最后给出更多产品入口和客服支持。

## 4. 顶部导航

导航组件为 `Navbar`，采用 sticky 顶部固定结构。主要功能包括：

- 品牌 Logo：`TITANIUM WORKSHOP`
- 桌面端导航：首页、产品、品牌、商店、新闻、服务
- 搜索按钮
- 移动端菜单按钮
- 移动端展开菜单

导航视觉较克制，使用黑色半透明背景和 backdrop blur，既能和页面背景融合，又能在滚动时保持可读性。

## 7. 3D & VR 交互模块

3D 模块由 `Model3DViewer` 组件实现，是页面技术体验的核心。

### 7.1 设计目的

3D 模型用于让用户在网页中直接查看“人物拿杯子”的立体模型，增强产品真实感和互动性。它不是静态图片替代品，而是一个沉浸式产品体验模块。

用户可以：

- 左右拖动旋转模型
- 上下拖动调整视角
- 滚轮缩放模型
- 点击暂停/开启自动旋转
- 点击重置视角

### 7.2 真实 OBJ/MTL 渲染

当前模型资源位于：

`public/products/model/person-cup/`

包含：

- `1fc6efad408e0e29cd41b44a8aa88efc.obj`
- `material.mtl`
- `texture_pbr_20250901.png`
- `texture_pbr_20250901_metallic.png`
- `texture_pbr_20250901_roughness.png`
- `texture_pbr_20250901_normal.png`

渲染方式不是程序化造模型，而是基于真实 OBJ 文件和配套贴图渲染。

### 7.3 加载策略

为避免浏览器扩展和 Babylon 默认二进制加载方式冲突，当前实现没有直接使用 `SceneLoader.ImportMesh` 自动下载 OBJ，而是：

1. 使用 `fetch(modelUrl).text()` 读取 OBJ 文本。
2. 使用 `OBJFileLoader().importMeshAsync(...)` 解析 OBJ。
3. 通过 `material.mtl` 加载同目录贴图。

这样既保留了真实 OBJ/MTL 渲染，又规避了 `arraybuffer.responseText` 类型错误。

### 7.4 入场加载动画

首页新增 `PageModelLoadingOverlay` 组件，用于在用户进入页面时展示全屏加载动画。该动画实际对应 3D 模型加载过程，而不是普通装饰性开屏。

当前流程如下：

1. 用户进入首页后，页面主体和 3D 区域会正常挂载。
2. `PageModelLoadingOverlay` 以 `fixed inset-0 z-[9999]` 覆盖页面，并暂时锁定 `body` 滚动。
3. `Model3DViewer` 开始加载真实 OBJ 模型、MTL 材质和贴图。
4. 当 OBJ 解析完成、模型 mesh 存在、相机完成自动取景后，`Model3DViewer` 触发 `titanium:model3d-ready` 事件。
5. `PageModelLoadingOverlay` 监听到该事件后隐藏，恢复页面滚动，用户进入正常页面。
6. 如果模型加载失败，`Model3DViewer` 会触发 `titanium:model3d-error`，全屏加载层显示错误提示，引导用户刷新重试。

这个设计的目标是确保用户进入页面时看到的是已经准备好的 3D 体验，避免页面先出现但 3D 区域长时间空转。需要注意的是，当前仍然使用原始 OBJ 资源，没有压缩、没有转 GLB，也没有替换成其他模型。

### 7.5 相机控制

3D 相机使用 Babylon.js `ArcRotateCamera`，适合围绕模型旋转查看。

当前关键交互处理包括：

- 自动旋转通过 `camera.alpha += 0.003` 实现。
- 用户在 3D 区域按下鼠标后，会自动暂停自动旋转，避免左右拖动时被自动旋转覆盖。
- 自动旋转状态通过 `autoRotateRef` 保持最新状态，避免 React 闭包状态过期。
- 重置按钮会恢复初始角度、目标点和缩放半径。

### 7.6 滚轮冲突处理

页面曾出现“鼠标在 3D 区域滚轮缩放模型时，页面也跟着滚动”的问题。当前已做处理：

- `camera.attachControl(canvas, false)` 让 Babylon 阻止默认滚轮行为。
- 额外给 canvas 添加 `wheel` 监听器，并调用 `event.preventDefault()`。
- canvas 设置 `touchAction: 'none'`，减少触控手势与页面滚动冲突。

因此鼠标停留在 3D 区域时，滚轮只用于模型缩放，不再滚动页面。

### 7.7 材质不透明处理

为避免 OBJ 材质被误判为透明，当前对加载后的材质做了统一处理：

- `alpha = 1`
- `transparencyMode = MATERIAL_OPAQUE`
- `backFaceCulling = false`
- `diffuseTexture.hasAlpha = false`
- 禁用 `opacityTexture`

这样可以最大限度避免贴图或材质在网页端出现不必要的透明效果。

### 7.8 环境贴图处理

页面曾加载 Babylon 官方 `.env` 环境反射贴图，但该资源是二进制格式，容易触发浏览器扩展读取 `responseText` 的报错。当前已移除外部 `.env` 环境贴图，改为纯灯光方案。

灯光包括：

- HemisphericLight
- Directional key light
- Directional fill light
- Point rim light

这种方案牺牲了一部分复杂环境反射，但稳定性更高，不再触发开发遮罩报错。

## 14. 当前已解决的关键问题

页面开发过程中已解决以下问题：

1. 图片裁切问题  
   重新生成并替换了部分产品场景图，保证比例更适合当前 4:3 展示区域。

2. 图片内中文问题  
   将产品图中的中文文案替换为英文，确保页面面向英文用户时视觉一致。

3. Edge 视频黑屏问题  
   将视频转码为 H.264/AAC 版本，提升 Edge 兼容性。

4. 3D 模型位置过高问题  
   通过完整模型 bounding box 计算相机 target 和 radius，使模型居中显示。

5. Next hydration 错误  
   将 `SmartCS` 从 `<html>` 直接子节点移动到 `<body>` 内部。

6. 3D 贴图加载错误  
   改为使用用户提供的 OBJ/MTL/贴图资产，并按真实模型渲染。

7. `responseText / arraybuffer` 开发遮罩问题  
   改用文本方式读取 OBJ，并移除外部 `.env` 二进制环境贴图。

8. 3D 滚轮与页面滚动冲突  
   在 canvas 上拦截 wheel 默认行为，确保滚轮只缩放模型。

9. 3D 左右拖动无效问题  
   修复自动旋转覆盖 `camera.alpha` 的问题，用户拖动时自动暂停自动旋转。

10. 材质透明感问题  
   对加载后的 OBJ 材质强制不透明和双面显示，减少网页端透明异常。

11. 127.0.0.1 开发资源跨源问题  
   Next.js dev server 默认会阻止部分 `127.0.0.1` 来源访问 `/_next/webpack-hmr` 等开发资源，可能导致客户端 hydration、按钮事件和 3D 初始化异常。当前已在 `next.config.ts` 中加入 `allowedDevOrigins: ['127.0.0.1', 'localhost']`，保证本地通过 `127.0.0.1:3000` 访问时客户端脚本能正常运行。

12. 页面入场 3D 加载体验  
   新增 `PageModelLoadingOverlay`，在模型加载完成前展示全屏 loading。`Model3DViewer` 加载完成后通过 `titanium:model3d-ready` 通知遮罩消失；加载失败时通过 `titanium:model3d-error` 通知遮罩显示错误状态。

## 15. 设计亮点

### 15.1 高端感与功能性平衡

页面没有过度依赖复杂动画，而是通过深色背景、暗金点缀、产品图、3D 模型和结构化信息建立品质感。视觉克制，但功能完整。

### 15.2 文化叙事与商品转化结合

页面不是单纯讲参数，而是将汉代天马、丝路文化、纯钛工艺和日常使用场景结合起来。这样更适合高客单价礼品或工艺品类产品。

### 15.3 3D 交互提升信任感

通过真实 OBJ 模型，用户可以旋转查看人物拿杯子的形态。相比静态图，3D 模型更能增强“真实产品展示”的感觉。

### 15.4 客服降低决策阻力

右下角智能客服可以回答材质、颜色、物流、售后、保养等问题，适合在用户犹豫时提供辅助信息。

## 16. 当前限制与后续优化建议

### 16.1 3D 模型体积较大

当前 OBJ 约 100MB，纹理也较大。虽然能真实展示模型，但会带来加载慢、首屏卡顿和移动端性能压力。

当前实现策略：

- 保留原始 OBJ/MTL/贴图，不压缩、不转 GLB、不替换模型。
- 通过进入页面的全屏 loading 明确告知用户正在准备 3D 模型。
- 只有当 `Model3DViewer` 完成模型解析、材质处理和相机取景后，才隐藏全屏 loading。
- 这样优先保证展示内容与用户提供的原始 3D 资产一致。

如后续允许性能优化，可以再考虑：

- 将 OBJ 转为 GLB。
- 使用 Draco 或 Meshopt 压缩。
- 降面到适合网页展示的级别。
- 将 4096 纹理压缩为 KTX2 或提供 2K 版本。
- 根据设备性能提供高/低精度模型切换。

这些优化属于后续性能方案，不是当前版本的实现目标。

### 16.2 客服仍是本地关键词匹配

当前客服适合展示和基础 FAQ，但不是完整智能客服。

后续可接入：

- 后端 FAQ API
- 向量检索
- LLM 对话服务
- 商品库存/订单接口

### 16.3 购买按钮尚未接入交易链路

`Buy Now` 和 `Add to Cart` 目前是视觉按钮，没有完整购物车或支付流程。

后续可以补充：

- 购物车状态
- SKU 选择
- 数量选择
- 支付流程
- 下单表单

### 16.4 搜索栏尚未接入真实搜索

导航中的搜索栏目前仅有输入交互，没有搜索结果页或过滤逻辑。

后续可以实现：

- 产品名称搜索
- 标签过滤
- 搜索建议
- 搜索结果页

## 17. 总结

该页面的核心价值在于把纯钛杯产品从普通商品展示升级为“高端工艺品体验页”。它通过深色金属视觉、文化叙事、主推商品信息、产品场景图、真实 3D 模型和智能客服，共同构建了一个完整的品牌展示与转化路径。

从用户体验角度看，页面具备清晰的浏览顺序：

3D 模型准备 → 品牌认知 → 主推产品 → 3D 体验 → 场景卖点 → 产品矩阵 → 客服咨询 → 转化入口

从技术实现角度看，页面已经具备较完整的前端交互能力。当前版本选择保留原始 OBJ/MTL/贴图资产，并通过入场 loading 管理等待体验；3D 模型资产体积仍是后续性能优化的重点。
